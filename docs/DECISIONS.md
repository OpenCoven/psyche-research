## D001: curated overlay before a file archive

Select a curated practitioner research publication with structured original notes and links to author-managed artifacts. This is an independently operated publication record over existing artifact hosts, rather than a replacement general-purpose repository or a claim to compete with mature preservation services. Compare alternatives in [RESEARCH.md](RESEARCH.md). Durable artifact preservation, DOI registration, academic recognition, demand and repeat readership are unverified hypotheses. Stable application version URLs and JSON citation metadata are implemented locally; domain ownership and long-term operation are not established.

First useful formats are experiments/replications, practice reports including negative results, tools/datasets, and evidence-supported ideas. Contributors supply methods, claims, limitations, provenance, license and AI-assistance disclosure. Artifacts are optional where no shareable artifact exists; methods and provenance remain required and must explain the evidence. The question belongs in the abstract/methods rather than a separate mandatory field. Public bylines are contributor supplied; ORCID and external profiles are not implemented identity features.

## D002: one Django application and a bounded relational database

Select Django 5.2 LTS with server-rendered forms and framework authentication/CSRF. SQLite was the initial local/persistent-host recommendation; the user selected Vercel during implementation, so D007 supersedes the hosted database choice with managed PostgreSQL. SQLite remains a local development and recovery-test backend. Django 5.2.19 was checked against the [official download page](https://www.djangoproject.com/download/) on 2026-11-04. A clean dependency installation and exact hashes are recorded in requirements.txt. SQL is limited to ORM queries, migrations and local recovery operations. No runtime LLM, outbound URL fetch, agent runner, uploads, code execution, JavaScript bundle, analytics service, background worker, object store or production credential is required.

SQLite BEGIN IMMEDIATE serializes write limits and workflow transitions across connections. Queue and draft counts are checked in the same transaction. A real-file separate-connection race is tested; shared-memory SQLite locking is not the supported deployment model. A lock timeout returns a controlled retry response. The Vercel target now requires PostgreSQL immediately; row locks on the same capacity singleton serialize service transitions across function instances. PostgreSQL portability has separate live-backend CI tests and cannot be accepted from SQLite results. Recovery uses bounded 64 MiB in-memory SQLite snapshots and refuses larger databases pending a reviewed replacement. Disk usage is an operating pause criterion before that bound, not an invitation to grow unbounded.

Linked artifact references avoid unsafe file intake and storage costs. Up to eight HTTPS references are accepted, each at most 2,000 characters; query tokens, userinfo, local hosts and private IP literals are rejected. URLs remain escaped text and are never fetched. Methods can cite other sources as text. A future upload/object-store path needs separate privacy, rights, validation, scan and preview design.

## D003: open eligibility with finite human capacity

Accounts are provided by the human operator, without GitHub, institutional affiliation, employer prestige, social metrics or payment. Provisioning and role commands exist but no real participant accounts or credentials have been created. A moderator is an active human account explicitly in the moderators group; staff/superuser flags do not grant moderation. The operator owns the host and can still bypass application controls, so audit is not tamper-proof.

Default capacity is intake paused, five queued submissions, one queued per contributor, two active drafts/changes/submissions per contributor and twenty active records globally. Text bodies are capped at 96 KiB with per-field limits. Persistent fixed-minute rate limits allow sixty authenticated mutations per minute and ten anonymous attempts per minute; login also has a per-username bucket. These are abuse bounds, not proof against distributed attacks. Reports are capped at ten unresolved per public work and one hundred globally. Appeals have one open per submission, one substantive appeal per exact decision and at most three per submission; exceptional requests require operator assessment. Production intake cannot open unless PILOT_APPROVED is explicitly configured after acceptance. The four-week/ten-participant/ten-total-submission pilot contract is a proposed manually tracked total, not an automatic signup quota.

## D004: freeze, decide, publish and correct

Save uses an optimistic revision counter; stale tabs cannot overwrite accepted saves. Submitting freezes canonical JSON and SHA-256. Moderator decisions identify actor, exact revision/digest, scope (moderation only), reason, conflict declaration and time. Authors cannot moderate their own submission, including when they are moderators or superusers. An identical lost-response submit/decision retry is idempotent. Changes requests unfreeze through a new revision. A later publication creates a new immutable Version with a stable work/version URL and correction note.

Versions, decisions and audit events are append-only at both the model and SQLite trigger boundaries. Table-rebuilding migrations explicitly reinstall triggers in both directions; tests inspect the current schema and independent review exercised reverse/reapply. This protects ordinary application writes and direct UPDATE/DELETE, not a privileged database owner who can drop triggers.

An author or moderator can immediately withdraw a whole work with a public safe reason. All versions become tombstones, and manuscript content disappears from public HTML, discovery and JSON exports. Old external downloads/caches cannot be recalled. Raw private records remain in the restricted database according to the to-be-adopted retention policy. Restoring an older backup must reconcile takedowns, withdrawals and revoked access before any serving cutover.

## D005: separate trust signals and keep assistance optional

Publication is availability of a specific version. Moderation checks scope, completeness, rights, privacy, safety and abuse, not scientific validity. Human scientific reviews and public vouches are not available and are a later milestone with exact-version/scope/conflict/revocation requirements. No record may silently inherit endorsement after revision. Automated checks are completeness and application safeguards only.

Familiar assistance is a human-run preparation option described in [ASSISTANCE.md](ASSISTANCE.md), not a runtime integration or publication identity. The full core workflow works with no provider key or network. Reputation research is disabled and unimplemented; [REPUTATION.md](REPUTATION.md) is a protocol for a later optional isolated shadow study, with no product join or decision influence. No scores, followers, stars, votes or social profiles participate in accounts, intake, queue ordering, publication, search or visibility.

## D007: user-selected Vercel target and managed PostgreSQL

The user selected Vercel while local verification was in progress. Prepare the existing Django application for its native Python/WSGI integration, using managed PostgreSQL for durable records and static-only CDN collection. [Vercel’s current Django documentation](https://vercel.com/docs/frameworks/full-stack/django) describes this deployment path; source configuration is not proof that this project has been built or deployed there. See [VERCEL.md](VERCEL.md) for the reviewable target packet.

DATABASE_URL selects PostgreSQL; VERCEL=1 refuses SQLite and local development mode. Production requires verify-full TLS and an approved CA trust source, bounded connection/statement/lock times, no persistent application connection and no prepared statement assumption for transaction pooling. Core mutations lock the capacity row; rate buckets have row locks. Vendor-specific migrations install equivalent PostgreSQL append-only update/delete/truncate guards. The read-only verify_archive command checks current schema columns/migrations, exact reject-function/trigger contracts and publication digests. Managed provider, region, pooling compatibility, backup/PITR, separate migration/runtime permissions and actual hosted concurrency/recovery remain acceptance gates.

No database or Vercel project was provisioned, no credentials or terms were created/accepted, and no deployment was authorized. Domain, contact and monthly cap were not supplied with the target choice. Migrations must run as an approved serialized operator step against the correct database, never automatically during every preview build. Preview databases/roles must be isolated from production and private participant material. SQLite snapshot commands explicitly refuse PostgreSQL and do not establish managed-provider recovery. The nginx/Gunicorn examples remain an alternative-host candidate only; Vercel uses its own runtime and logging boundary.
