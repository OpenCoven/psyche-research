## Finding, regression and correction

Follow-up review found that the first repair wrapped anonymous OAuth callbacks in the request transaction too. The callback's inner consumption transaction then became a savepoint: its deletion was not committed before the external authorization-code exchange. A process failure after that exchange could leave the attempt reusable. [Django's transaction documentation](https://docs.djangoproject.com/en/5.2/topics/db/transactions/) confirms nested atomic blocks do not independently commit; it documents `durable=True` for an outermost commit boundary. This is a correction to this run's own unpublished repair, not a finding in the delivered main revision.

The added real-file regression opens a separate ordinary database connection from the provider-exchange stub and requires it to observe zero pending attempts before the external exchange begins. Its first run failed with `Independent connection observed unconsumed callback state: [1]`; the callback returned 503. The private original log is retained at `var/postgres-qualification/callback-commit-first-failure.log`.

Session serialization now applies only when the persisted session is authenticated. Anonymous OAuth sessions retain the callback's independent consumption transaction; callback consumption also uses `transaction.atomic(durable=True)` to reject an unexpected production outer transaction before sending an exchange. Authenticated overlapping requests still lock before loading their session caches and through response saving. The refresh-race regression and downstream-server-error rotation regression remain green. No schema, role, secret or identity binding changed.
